# Задание 1. Исследование моделей и инфраструктуры


## 1. Сравнение LLM

| Критерий | Локальные HF (Llama/Mistral) | OpenAI GPT | YandexGPT |
|---|---|---|---|
| Качество | Хорошее на 7–70B, зависит от железа | Отличное, стабильные инструкции | Хорошее на RU, удобно для РФ/СНГ |
| Скорость | Зависит от GPU; CPU медленно | Высокая через API | Высокая через API |
| Стоимость | CapEx (GPU) + электричество; OpEx низкий | Pay-per-token, предсказуемо на PoC | Pay-per-token, часто дешевле на RU |
| Деплой | Сложнее (vLLM/TGI, квантизация) | Проще всего | Простой API, нужен каталог Yandex Cloud |
| Конфиденциальность | Данные остаются on-prem | Данные уходят к провайдеру (нужен DPA) | Данные в Yandex Cloud (нужен DPA) |

**Вывод для QuantumForge:** для учебной реализации — облачный LLM *или* extractive-режим без API. Для продакшена с SOC 2 — on-prem/VPC LLM либо enterprise-контракт с запретом training на данных клиента.

## 2. Сравнение эмбеддингов

| Критерий | Sentence-Transformers (all-MiniLM-L6-v2) | OpenAI Embeddings |
|---|---|---|
| Скорость индекса | Быстро на CPU (~22–90 МБ модель) | Зависит от сети/квот API |
| Качество поиска | Достаточно для FAQ/вики на EN/простом RU | Выше на сложных парафразах |
| Стоимость | Почти 0 после скачивания | $/1M tokens постоянно |
| Приватность | Полностью локально | Текст уходит в API |

**Выбор:** `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (384 dim) — Учебный.

## 3. Сравнение векторных БД: ChromaDB vs FAISS

| Критерий | FAISS | ChromaDB |
|---|---|---|
| Скорость поиска/индексации | Очень высокая in-process | Высокая для PoC, хуже на десятках млн |
| Внедрение | `pip install`, 5–10 строк | Тоже просто, «pythonic» API |
| Метаданные/фильтры | Нет из коробки (сами) | JSON-метаданные и фильтры |
| Поддержка | Нужен свой слой обновления/бэкапа | Удобнее коллекции, но скейл ограничен RAM |
| Стоимость | Только инфраструктура хоста | То же (embedded) / сервер |

**Выбор для проекта:** **FAISS** — Учебный. Для следующего этапа QuantumForge (мультикомандный прод) — миграция на **Qdrant** (фильтры, on-prem→cloud).

## 5. Итоговые варианты конфигурации

### Учебный 
- LLM: extractive / опционально OpenAI  
- Embeddings: paraphrase-multilingual-MiniLM-L12-v2  
- VDB: **FAISS**  
- Интерфейс: FastAPI + Telegram  
- **Плюсы:** соответствует заданию, дешево, воспроизводимо в Docker.

### Рекомендуемый для компании
- LLM: YandexGPT или VPC  
- Embeddings: локальные Sentence-Transformers  
- VDB: Qdrant (self-host в Tallinn R&D / Helsinki)  
- **Плюсы:** контроль эмбеддингов и индекса, облачная генерация по договору.  
- **Минусы:** нужна эксплуатация Qdrant.
